# DSH XC 安装与使用说明

> 适用对象：**正式版（Release）桌面应用**。本文面向最终用户；开发者构建与调试请见[中文开发指南](./DEVELOPMENT.zh.md)。

## 一、DSH XC 是什么

DSH XC 把 DeepSeek Harness（`dsh`）装进桌面：在一个窗口里运行本地 Harness 界面、模型与插件。无需自行安装 Node.js、pnpm 或 Docker，首次启动会联网补齐运行时与内核。

- 本地会话、代码执行、Git 工作树
- 插件安装、升级、卸载与插件市场
- 手机 / 远端连接，局域网与公网隧道
- 桌宠、主题配色、命令行集成

> **安全提示**：`dsh` 具备本地代码执行能力。建议只在可信、隔离的环境中使用；升级前留意插件与内核的兼容性。

## 二、系统要求

| 平台 | 最低要求 | 说明 |
| --- | --- | --- |
| Windows | Windows 10+ | 内置 Chromium 内核，无需另装 WebView2 |
| macOS | macOS 12+ | 支持 Intel 与 Apple Silicon |
| Linux | 主流 x64 发行版 | 内置 Chromium 内核；deb 依赖 `zenity`、`libudev1` |

其他前提：

- 首次启动需联网下载运行时与内核；带 `Bundle` 后缀的离线包可免去这一步。
- Git 功能需要系统已安装 Git。
- 网络访问受限时，可在设置里配置代理（见「常用设置」）。

## 三、安装

安装包统一从 [Releases 页面](https://github.com/dsh-tauri/deepseek-harness-desktop/releases)下载，选择标注为正式版（非 pre-release / nightly）的资产。

### 3.1 Windows

1. 下载 x64 的 `.exe` 或 `.msi` 安装包。
2. 双击运行，按向导完成安装；安装过程中可选择数据存放位置。
3. 从开始菜单或桌面快捷方式启动。

离线用户下载带 `Bundle` 后缀的 `_Bundle_*.exe`，内置运行时与内核。

### 3.2 macOS

1. 按芯片下载对应 `.dmg`：Apple Silicon 选 aarch64，Intel 选 x64。
2. 打开 dmg，把应用拖入「应用程序」。
3. 首次打开若提示「无法验证开发者」，前往 **系统设置 → 隐私与安全性 → 仍要打开**。

也可用 Homebrew 安装：

```bash
brew install dsh-tauri/desktop/deepseek-harness
```

离线用户下载 `_Bundle_*.dmg`。

### 3.3 Linux

- **AppImage**：下载 `.AppImage`，赋予执行权限后运行（部分发行版需安装 FUSE）。

  ```bash
  chmod +x DSH*.AppImage && ./DSH*.AppImage
  ```

- **Debian / Ubuntu**：下载 `.deb` 后安装。

  ```bash
  sudo dpkg -i dsh-*.deb && sudo apt -f install
  ```

- **Fedora 43+**（x64 / ARM64）通过 Copr 安装，升级随 `dnf upgrade` 进行：

  ```bash
  sudo dnf copr enable fairyband/dsh-tauri
  sudo dnf install dsh-tauri        # 正式版
  ```

  想跟进预发布版可改装 `dsh-tauri-beta`（两者互斥）：`sudo dnf swap dsh-tauri dsh-tauri-beta`。

> 由系统包管理器安装时，应用内自动更新会关闭，请用对应包管理器升级。

### 3.4 验证安装

启动后出现主窗口，顶部本地实例状态显示「已连接」即安装成功。首次启动有 1–2 分钟初始化（下载依赖、加载插件），期间状态栏会显示「正在安装依赖…」「正在加载插件…」。

## 四、首次启动

1. **初始化**：自动下载 Harness 内核与依赖；进度显示在状态栏。内核版本由应用内置清单决定，无需手动指定。
2. **启动引导**：可按需勾选社区插件预设（桌宠、Office Kit、社区市场等）。之后随时可在插件页补装。
3. **命令行集成**：正式版默认开启，自动把 `dsh` / `pnpm` 加入 PATH。**需重新打开终端才生效**；部分第三方 shell 仍需手动配置。
4. **配置模型**：在设置中配置模型与 API 密钥后即可开始对话。

若卡在启动阶段，见「常见问题」。

## 五、界面与日常使用

### 5.1 主窗口与托盘

- 最小内容尺寸为 860 × 620。
- 点击窗口 **X**：默认「隐藏到托盘」，进程仍在后台运行；点击托盘图标或「打开面板」恢复并聚焦窗口。
- 托盘菜单的「退出」结束应用。
- 如需改为点 X 直接退出，在设置中把关闭行为改为「退出应用」。
- 内嵌页面支持右键编辑菜单，`F12` 开关开发者工具（被禁用开发者工具的页面除外）。

### 5.2 开始一个会话

1. 在 Harness 界面新建会话，输入任务。
2. 首次使用前确认模型已配置；需要代码仓库时，用工作树功能创建会话级 Git 工作树。
3. 会话结束后可在「聊天归档」中恢复历史。

## 七、数据与配置

- **用户数据目录 `$DSH_HOME`**：默认 `~/.dsh`（Windows 为 `C:\Users\<用户名>\.dsh`），可用环境变量 `DSH_HOME` 覆盖。会话、档案、设置与凭证都在这里；桌面版与官方 Node 版 `dsh` 共用该目录，无需迁移。
- **应用数据目录**：Windows 为 `%APPDATA%\dsh-tauri\`，macOS / Linux 遵循系统应用数据约定。其中 `logs\` 存放应用与服务日志，`dependencies\dsh\` 存放下载的 Harness 发行版，`.store.dat` 保存桌面设置（端口、自启动、语言等）。
- **迁移与回滚**：Windows 安装时可选择数据位置；之后可在设置里整体迁移数据目录并回滚。
- **备份**：直接备份 `$DSH_HOME` 与应用数据目录即可。

## 八、更新与卸载

- **桌面端更新**：菜单 →「检查更新」，或开启「自动更新」（首次检查并在退出时安装）。包管理器安装的版本请用包管理器升级。
- **内核更新**：由应用内置清单管理，随桌面端一起校验下载；本地核心可用「更新本地核心」（需先切到受管核心）。
- **卸载**：Windows 通过「设置 → 应用」或控制面板；macOS 把应用拖入废纸篓；Linux 用 `apt remove` / `dnf remove` 或删除 AppImage。卸载不会自动删除 `$DSH_HOME`，如需彻底清理请手动删除（会丢失会话与凭证）。

## 九、常见问题

| 现象 | 处理 |
| --- | --- |
| 首次启动内容区长时间空白 | 确认网络可访问下载源；必要时配置代理后重试。带 `Bundle` 的离线包可避免下载环节。 |
| 请求失败 404 / `not found` | 多为内核版本与插件/路由不匹配。菜单 →「检查更新」升级桌面端与内核，或重启应用让其重新匹配兼容版本。 |
| `STARTUP_LOW_INTEGRITY`（Windows） | 进程完整性级别过低，无法写入正常用户数据。用 `icacls` 检查安装目录，把可信安装恢复为 Medium；以管理员身份运行**不会**解除该限制，通常重新安装到正常目录即可。 |
| 提示 Harness 意外停止 | 查看应用数据目录 `logs\` 下的服务日志；若提示内存耗尽，在「设置 → 服务内存上限」调高数值（1024–32768）并重启服务。 |
| 代理设置后下载仍失败 | SOCKS 代理只对桌面端请求与 `curl`/`git`/`pnpm` 等子进程生效，Harness 内的模型 API、MCP、插件市场请求不支持 SOCKS，会直连。保存代理后需重试失败的操作。 |
| 手机无法连接远程 | 确认电脑、Harness 与所用隧道均在线；不要公开二维码或访问码。远程访问并非只读。 |
| 想切换原生窗口透明模式 | 在设置里修改后需**完全退出**应用再打开；关闭到托盘不会重启应用。 |

日志位置：应用数据目录下的 `logs\desktop.log`（Windows 为 `%APPDATA%\dsh-tauri\logs\desktop.log`）。反馈问题时附上相关日志与复现步骤。

## 十、安全与隐私

- `dsh` 可执行本地代码，请在可信环境中使用，谨慎对待来源不明的插件与会话内容。
- 远程分享会开放对本地 Harness 的访问，请勿公开二维码与访问码。
- 外观等设置仅保存在本机，不同步到其他客户端；会话与凭证存放于本地 `$DSH_HOME`。
