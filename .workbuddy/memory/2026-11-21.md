## 收窄无用构建（paths-ignore + gate 修复）

- 应用户要求把 push 触发的 `paths-ignore` 从 `README.md` 改为 `**.md`（改文档不再触发构建）。
- 推送后发现**真实缺陷**：gate 步骤原本只在 `schedule` 事件下跳过已发布 tag，push 事件不跳过 → 每次 push 都会重跑完整构建，最后 `gh release create` 因 tag 已存在而失败（红 run）。这与"长期稳定"冲突。

- 验证：新 run 44874777616（push 触发）gate 正确 skip，所有构建步骤 skipped，仅数秒完成，不再消耗额度。

**L2 关键坑（下次必记）**：该设置被持久化进 `pnpm-lock.yaml` 的 `settings` 段，键名合法化后 `pnpm install --frozen-lockfile` 直接报 `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`，必须重新生成锁文件。重新生成会顺带产生无关的重新解析漂移（本次为 `@smithy/node-http-handler` 4.12.1→4.14.1、`@types/node` 22.20.5→26.6.6），需逐行还原，最终锁文件差异只应剩 `settings.injectWorkspacePackages: true` 一行。另：本地 `pnpm install` 判"Already up to date"不会重链，`node_modules/.modules.yaml` 仍 `injectedDeps: {}`、工作区依赖仍是符号链接（`--force` 也无效），物理注入只在全新安装发生 → 本地无法复现 CI 布局，验证存在盲区。

**L2 最终裁定：回退为删除死键（用户确认）**。依据：官方语义为"把工作区依赖改为硬链接，但默认 `dedupeInjectedDeps: true` 会尽量退回符号链接"；`.temp/inject-probe/` 用 pnpm 11.7.0 干净安装实测，无 peer 差异时仍是符号链接；真实仓库 25 条 `workspace:` 边中 4 条 peer 图不一致会物理硬链接（`dsh-tauri-bundle→dsh-tauri-model`，`dsh-tauri-model→dsh-tauri / dsh-tauri-ui / dsh-tauri-config`），而仓库未配 `syncInjectedDepsAfterScripts`，官方明确硬链接副本不随源码增删同步，对需构建的 TS 包有陈旧风险。故删除该行（`pnpm-workspace.yaml` 与锁文件各删 1 行），锁文件已与修复前备份逐字节一致（diff 退出码 0），`--frozen-lockfile` 通过。最终保留的改动仅为 M3（5 个 README）与 M1（两份开发文档）。
